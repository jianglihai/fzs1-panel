### 本副本相对原作做了什么

仅在 [@zzt718](https://github.com/zzt718) 的原作之上新增，其余全部为原样：

| 版本 | 改动 |
| --- | --- |
| `0.3.2-1` | 修复 OpenWrt 23.05 上面板 **全部 AT 交互失效**：rpcd `file.c:812` 的 `if (sid && env) return PERMISSION_DENIED` 发生在任何 ACL 检查之前，而 LuCI 的 `fs.exec()` 必然带 `env` 键。改用只声明 `['command','params']` 的 `fzsexec` 模块绕开，共替换 7 个页面 28 处调用 |
| `0.3.2-1` | `build_ipk.py`：`control`/`postinst` 打包前统一 CRLF→LF（否则设备上 ash 报 `line 3: { : not found`，服务起不来） |
| `0.3.5` | 读卡自愈：面板概览页「重新初始化 SIM」按钮 + `fzs-at sim status/reset` + 开机自愈服务 `fzs-simretry`（模组 `QSIMDET=0,0` 导致开机握手失败就永久无卡，这层把它变成"过一会儿自己好了"） |
| `0.3.7` | **AT 口一律动态发现**：新增 `probe_at()` —— 真的发一条 `AT`、必须回 `OK` 才认这个口（结果缓存 60 s）。原逻辑把 USB 接口 `:1.4` 写死当 AT 口，而那是 Quectel 的 PPP/modem 口、被 `pppd` 独占，`open()` 直接 `EAGAIN`；换卡槽触发 USB 重枚举、ttyUSB 编号整体平移后就表现为「模组无响应 / 发不了短信」。代码中已无任何写死的 ttyUSB 编号 |
| `0.3.7` | `fzs-at` 保留 IMS 原生栈旁路能力：`native_ims_target` / `cmd_ims_native` / `cmd_ims_learn`（P-CSCF 自学习），未装 imsengine 时自动回退原生 CS 域 |
| `0.1.21` | **修掉最后一个锁坑**：`start_bypass_watch` 的后台子 shell 会继承 rc.common 的 `fd 1000`（`/tmp/lock/procd_ims.lock`）。flock 跟着这个打开文件描述走，父 shell 退出不释放 —— 只要守望进程活着锁就永远被占，于是 `ims start` 明明返回了，后续 `ims running`、`mwan3 status` 全部永久卡死（症状：网页终端不动、面板 init.d 操作无响应，opkg 安装也会卡在 prerm 的 `ims stop`）。改为在子 shell 里 `1000>&-`：锁随最后一个引用消失而释放 |
| `0.1.20` | 引擎新增 `ims-atport`（唯一的动态端口枚举器：sysfs `idProduct` + 接口号 `>= :1.3`，`:1.4` 优先）与 `ims-submit`（文件交互式发短信，**完全绕开 `rc.common` 的 `procd_lock`**，修掉发短信无限卡死）；`native_self_detect` / 诊断段 / `ims-data` 全部改走 `ims-atport`；修掉 `start_bypass_watch` 吊住 procd 管道 + 子 shell 抢父进程锁造成的自锁；postinst 不再同步调 `restart`，opkg 安装不再阻塞 |

> 上述任何问题**均由本副本的改动负责**，请不要反馈到原作者那里。
> 若想参与这个面板本身的开发，请直接到 **[zzt718/fzs1-panel](https://github.com/zzt718/fzs1-panel)** —— 那里才是它的家。

## 仓库结构（面板 + IMS 引擎同仓）

2026-10-25 起，原来的固件编译仓库 `fzs1-openwrt-ims` 已停用删除，**引擎源码并入本仓库**，
改插件不再需要碰 OpenWrt 固件编译链：

```
fzs1-panel/
├── src/                  面板源码 luci-app-fzs（+ fzs-atio / fzs-push / build_ipk.py）
│   └── dist/             面板 ipk 产物（.gitignore，本地生成）
├── engine/               ★ IMS 引擎（原 fzs1-openwrt-ims）
│   ├── imsengine/            Go 源码
│   ├── board-files/          设备上实际落地的文件（init.d/ims、patch-fzs …）
│   ├── mkpkg.py              打包：引擎 ipk + 面板 ipk 重封 + 恢复包
│   └── build-engine.sh       交叉编译引擎（MIPS mipsle softfloat）
├── build-all.sh          一条命令出两个 ipk
└── build/packages/       最终交付产物（.gitignore）
```

**打包：**

```bash
bash build-all.sh                 # 面板 + 引擎，两个 ipk 一次出
bash build-all.sh 0.3.7 0.1.21    # 指定面板版本 / 引擎版本
```

设备端安装**必须两个包一起装**（先面板、后引擎），只装面板会看不到 IMS 入口 ——
面板检测不到引擎时会把「IMS 通道」选项主动隐藏，这是设计如此。
细节见 [engine/README.md](engine/README.md)。

## 这是什么

社区的 OpenWrt 固件把 MIBOX-668M2 变成了一台真正的 OpenWrt 路由器（双模组 RNDIS + mwan3 + LuCI），
但蜂窝侧的能力只有 SSH 命令行——LuCI 里什么都看不到。

这个面板把这些能力做成**中文图形界面**，让不用命令行的用户也能：

- 一屏看清**两个模组**的信号、运营商、驻网频段、小区；
- 锁频段 / 锁频点 / 锁小区；
- 收发短信，并把短信自动转发到手机 App 或群机器人；
- 读改 IMEI、设置 APN、开关 4G 数据。

> 固件本身由社区开发者编译（本项目不提供固件），本项目只交付插件（ipk）。

## 适用设备与系统要求

| 项目 | 要求 |
|---|---|
| 设备 | **蜂助手 S1 / MIBOX-668M2**（MT7628 + Quectel EC200T + EC200N 双模组） |
| 系统 | **OpenWrt 22.03 及以上**（LuCI 客户端 JS 版） |
| 依赖 | 无外部依赖（只依赖 `luci-base` / `rpcd` / 标准 `libc`） |

**两点如实说明**：

1. **必须是 22.03 或更高**。面板使用 LuCI 客户端 JS 架构，21.02 及更早（Lua 版 LuCI）不会被加载。
2. **「上网设置」页需要固件自带那套平台脚本**（`/etc/config/mifi` 等）。换其它固件后，该页可能失效，**其余功能不受影响**——锁频/锁小区/IMEI/短信都是直接操作模组。

> 本项目**只在 OpenWrt 22.03.7 上实测**；23.05 / 24.10 理论兼容（只用了稳定的 LuCI API），未实机验证。

## ⚠️ 短信：先说最重要的一条

| 卡插在 | 短信域 | 实测表现 |
|---|---|---|
| **EC200N 槽（模组2）** | **IMS** | **秒级收到，各运营商一致** |
| **EC200T 槽（模组1）** | **CS** | 15~30 秒；**部分联通卡、电信卡收不到短信** |

⇒ **想要稳定、快速的收信体验，请把卡插在 EC200N 槽。**

原因是模组能力差异：EC200T 的固件不支持 VoLTE/IMS（`AT+QCFG="ims"` 直接返回 `+CME ERROR: 4`），
短信只能走 CS 域；而 CS 域短信在部分运营商网络上已被弱化。这不是软件能改变的。
（技术细节见 [短信实现详解](短信实现详解.md)。）

### 怎么换成社区 OpenWrt 固件

**固件从哪来**：本设备的社区 OpenWrt 固件由 **羁穗**（酷安）编译发布——**到他发布的帖子里获取固件**。

**怎么刷**（作者帖里没有细说，这里补上）：

> 🔑 **原厂固件用户先看这里：8888 后台进不去怎么办？**
> 原厂固件的 8888（LuCI）密码是出厂设置的、没人知道，所以要先清掉它：
> 1. 浏览器手动打开 **`http://192.168.1.1/SysCommand.htm`**（原厂 80 后台的「系统命令行」，账号密码都是 `admin`）；
> 2. 在里面执行一条命令：**`passwd -d root`**（清除 root 密码）；
> 3. 回到 **`http://192.168.1.1:8888`**，用户名 `root`、**密码留空** → 即可登录。
>
> （已在用姊妹项目 fzs1-decloud 的用户：工具箱里有「管理后台密码」，设一个就能进，不需要这一步。）

1. 浏览器进入设备的 **OpenWrt 后台（LuCI）**；
2. 左侧菜单 → **系统 → 备份 / 刷写固件**；
3. 页面下半部分「**刷写新固件**」→ 点「选择文件」，选中刚下载的固件；
4. ⚠️⚠️ **不要勾「保留当前配置」** —— **这一条务必记住**：
   原厂固件的配置和社区固件**不兼容**，勾了会导致**设备刷完启动不起来**（真实踩过的坑）；
5. 点「刷写固件…」→ 确认 → 等设备自动重启（约 1~2 分钟，中途不要断电）。

**刷完自检**：

- LuCI 后台能打开（`http://192.168.1.1`）；
- 用面板的概览页（或 `mifi-at ports`）能看到**两个模组**都识别到。

> 💡 记住一条通用规则：**跨系统刷写（原厂 ↔ 社区）一律不勾"保留配置"**——
> 两边配置文件格式不同，保留就会启动异常。本文档后面「想回到原厂固件」一节同理。

⚠️ **三条提醒**：

1. **刷机会清掉现有系统**——厂商云控、原有工具箱都会消失，动手前请想清楚；
2. **原厂固件用户建议先备份**（备份与回原厂方法见 [想回到原厂固件](#想回到原厂固件)）；
3. 刷完**后悔了想回原厂**，我们提供了回原厂镜像，同样见 [想回到原厂固件](#想回到原厂固件)。

## 安装（4 步，全在网页上）

本仓库现在交付**两个包**（面板 + IMS 引擎），**必须两个都装、先面板后引擎**
（只装面板时，面板检测不到引擎会把「IMS 通道」选项主动隐藏，这是设计如此）。

1. 到本仓库的 **[Releases 页面](../../releases/latest)** 下载最新版的
   **`luci-app-fzs_<版本>_all.ipk`**（面板）和 **`imsengine_<版本>_mipsel_24kc.ipk`**（引擎）
   （直链：`https://github.com/jianglihai/fzs1-panel/releases/latest`）；
2. 浏览器打开 LuCI 后台 → **系统 → 软件包** → 页面上方「**上传软件包…**」→
   **先装面板，再装引擎**（两个都装完再往下走）；
3. **服务 → 终端**（或 `http://设备IP:7681`）用 root 登录，**一次粘一条、等提示符回来再粘下一条**：

   ```sh
   /etc/init.d/rpcd restart                                 # 让 ACL 与菜单生效
   /etc/init.d/ims enable && /etc/init.d/ims restart        # IMS 引擎开机自启 + 立即拉起
   /etc/init.d/fzs-sms enable && /etc/init.d/fzs-sms restart # 短信/面板后端自启 + 重启
   ```

   > 三条都是**幂等**的，重复执行没有副作用。本机实测（`0.3.7` / `0.1.21`）：
   > 第 1 条约 1 s、第 2 条约 2–5 s、第 3 条约 1 s，全部返回 0。
   > 第 1 条不跑会出现「装好了但面板没数据 / 菜单不出现」。

4. ⚠️ **「退出登录」后再用账号重新登录一次** ——
   LuCI 的菜单是**登录时**生成的，**刚装完不退出重进是看不到新菜单的**（很多人在这一步以为没装上）。
   重新登录后，左侧「服务」分组下会出现「**蜂助手面板**」。

> 命令行也可以用：`opkg install luci-app-fzs_*.ipk imsengine_*.ipk`（零依赖，可离线安装）。

> 可选第 4 条：`/etc/init.d/fzs-simretry enable` —— 开机读卡自愈（面板包安装时已自动 enable，
> 这条只是核对）。**不要执行 `start`**，它是开机任务，手动跑一遍约 2 分钟且会占用 AT 口。

### 卸载

**系统 → 软件包 → 找到 `luci-app-fzs` / `imsengine` → 移除**（两个包互不锁定，先卸哪个都行）。
短信数据在 `/etc/fzs-sms/`、配置在 `/etc/config/fzs-sms`，**卸载不会自动删**（需彻底清理时手动删这两处）。

### 升级会丢数据吗？——不会

升级只替换程序，短信与设置原样保留：

| | 存放位置 | 升级时 |
|---|---|---|
| 短信（收件箱/发件箱） | `/etc/fzs-sms/`（不在安装包内） | 不动 |
| 转发 token、渠道配置 | `/etc/config/fzs-sms`（声明为配置文件） | 保留你的版本 |
| 程序 | `/usr/libexec/`、页面文件 | 被新版本替换 |

### 恢复包（免 opkg 的整机兜底）

Releases 里的 `fzs-ims-suite-<引擎版本>.tar.gz` **不是第三个插件**，也不用 `opkg` 装 ——
解压出来是一棵完整的文件树（`etc/`、`usr/`、`www/`），在 LuCI → **系统 → 备份/升级 → 恢复备份**
上传即可直接覆盖到 `/`。

| | ipk（面板 + 引擎） | 恢复包 `fzs-ims-suite-*.tar.gz` |
|---|---|---|
| 安装方式 | LuCI 软件包 / `opkg install` | LuCI「恢复备份」上传 |
| 适用场景 | **常规升级，优先用这个** | 整机兜底、opkg 用不了、想一次铺齐 |
| 对系统的影响 | 走 opkg 事务，可正常卸载 | 直接覆盖文件，**不走 opkg 事务**（包内自带 `fzs-ims-register-opkg` 补登记） |

> ⚠️ 恢复包会**直接覆盖同名文件**，装之前先备份 `/etc/config/`。
> 之所以还需要这条路：厂商固件的「刷写固件」框会直写 flash 固件分区，伪造镜像必砖；
> 而「恢复备份」本质只是 `tar -C / -xzf`，不碰分区，是唯一不碰 flash 的系统级通道。

### 概览

每个模组一张卡：型号、IMEI / ICCID / IMSI（默认打码，点眼睛临时显示）、RSRP 信号条与质量评价、
运营商、驻网频段 + EARFCN + PCI、SINR / RSRQ、注册状态。30 秒自动刷新，也可手动「立即刷新」。
页面底部有各功能入口，以及适用硬件、当前版本号与「关于」（许可 / 致谢 / 免责声明）。

### 上网设置

- **上网方式**（即时生效，约 40 秒）：仅用 4G / 仅用有线 / 有线优先 / 负载均衡（双卡）；
- **4G 模组开关**（需重启）：关闭后仅停止 4G 上网，**短信、锁频、IMEI 不受影响**；
- **网口**：三个网口图形化点选，选中者作 WAN（与设备丝印 LAN2 / LAN1 / LAN0 一致）。

> 切换基于 mwan3 多上行优先级，不重启设备；网络闪断数秒属正常。

### 锁频段

勾选 FDD / TDD 频段 → 应用 → 模组重新驻网并自动恢复拨号。

| FDD-LTE | TDD-LTE |
|---|---|
| B1 / B3 / B5 / B8 | B34 / B38 / B39 / B40 / B41 |

需要钉死在某个频点请用下一页。

### 锁定频点 / 小区

锁定后 75 秒内未驻网会自动解除；解除后自动补拨号。

### IMEI 改串

读 / 备份 / 恢复 / 写入。输入 14 位会按 Luhn 自动补全校验位，15 位校验位错误会给出修正建议；
写入有二次确认。**修改 IMEI 在法律上受管制，请只对本人合法拥有的设备、使用合法的值。**

### APN 与数据开关

每个模组可设 APN（auto / 运营商预设 / 自定义），并提供每模组的数据开关。

### 短信中心

- **长短信自动拼接**（按 UDH 分片重组）；

## 技术实现要点

> 完整的命令清单、PDU 结构、实测数据与代码说明见 **[短信实现详解](短信实现详解.md)**。本节只列要点。

**背景说明**：同型号设备上已有第三方的短信转发方案（该方案在 EC200T 槽走自研 IMS 栈、在 EC200N 槽走 AT 轮询）。
本项目的短信走 **AT + PDU 轮询**路线，以下是这条路线上的主要问题与处理方式。

### 一、收发一律走 PDU

模组固件（`EC200TCNHAR02A01M16_BETA0520_PS`）在文本模式下发送中文会失真——
模组确认提交（`+CMGS`），但运营商侧收到乱码。因此本项目**不使用文本模式**，
收、发全部走 PDU（`AT+CMGF=0`），自行编解码。

一次收信会话：

```
AT                    → OK
ATE0                  → OK
AT+CMGF=0             → OK
AT+CPMS="ME","ME","ME" → +CPMS: <used>,<total>,...
AT+CMGL=4             → +CMGL: <idx>,<stat>,<len>\r\n<PDU 十六进制>
```

发送：`AT+CMGS=<TPDU 字节数>` → 等 `>` → 送 PDU → 等 `+CMGS: <mr>` + `OK`。
PDU 首字节 `00`（不带 SMSC，用模组默认），`FO=01`（SUBMIT，相对有效期），
编码按内容自动选择 GSM7 或 UCS2。解码侧自行实现 GSM7 打包/解包、UCS2、UDH 长短信分片重组。

### 二、读 AT 的完整性判据

"没有输出"和"输出不完整"是两回事，只看"有没有输出"会漏数据。本项目使用的判据：

```sh
_want=$((2 + $#))                    # 2 = 会话开头固定的 AT + ATE0
_ans=$(printf '%s\n' "$buf" | grep -cE '^(OK|ERROR|\+CME ERROR|\+CMS ERROR)')
[ "$_ans" = "$_want" ] || 整会话重试  # 必须"恰好相等"
```

**为什么必须"恰好"而不能用 `≥`**：模组忙时 `AT+CMGL=4` 的响应会**整份出现两遍**
（实测 `OK=13`、索引 `0..6` 出现两次）。用 `≥` 会把重复数据当作成功放行，
导致长短信分片编号错乱、无法拼齐，收信延迟可达上百秒。

**三次重试仍不合格时返回"本轮读取失败"**，而不是返回可能重复的数据——短信仍在模组里，下一轮会读到，不会丢。

### 三、超时与"模组忙"

- 模组正常应答耗时 **1~9 毫秒**，因此单条超时设为 **800 毫秒**（约 100 倍余量）；
- **首条（`AT` 热身）超时即放弃本轮**——说明模组忙，后续每条都会超时，逐条等待没有意义；
- EC200T 在**接收并重组长短信期间，AT 接口整段无响应**（连 `AT` 都不回），这是模组行为，软件无法消除。

### 四、AT 引擎 `fzs-atio`

设备上的 shell 工具不具备亚秒级时间能力（`read -t` 只接受整数秒、`sleep 0.25` 实际只睡 0.04 秒、
没有 `stty` / `timeout` / `socat`），无法实现"发一条、等应答、再发下一条"的握手。
因此本项目内置一个 **C 语言编写的 AT 引擎**（静态编译，约 65 KB，不依赖设备上的任何库）：

1. **一次调用完成一个完整会话**，不反复开合串口；
2. **不触碰 DTR/RTS**（部分 4G 模组被 DTR 抖动会重新枚举）；
3. 逐条发送 → 等待应答（毫秒级超时）→ 命中 `OK` / `ERROR` / `>` 才发下一条；
4. 输出格式与旧方案逐字一致，上层解析无需改动；
5. 探测不到引擎时**回退到 picocom**，不会因工具缺失导致安装后不可用。

实测对比（同一台设备）：

| 操作 | 旧方案（picocom + 固定 sleep） | `fzs-atio` |
|---|---|---|
| 双模组状态查询 | 14.13 秒 | **0.53 秒** |
| 发送一条短信 | 13.5 秒 | **1.38 秒** |

源码在 `src/fzs-atio/`（GPL-3.0-or-later），编译脚本 `build.sh`。

### 五、转发渠道的两个细节

- 钉钉 / 飞书 / 企微群机器人要求 `POST + Content-Type: application/json`，
  而设备自带的 `uclient-fetch` 将该请求头写死为 urlencoded 且不可修改 ⇒ 改用 GNU `wget`（可自定义请求头）；
- **判断转发是否成功必须读取响应体**（`errcode==0` / `code==0` / `ok==true`），
  这些渠道**失败时同样返回 HTTP 200**。

## 已知限制

1. **EC200T 槽收信慢，且部分联通卡 / 电信卡收不到**（CS 域限制）——**请优先把卡插 EC200N 槽**；
2. 中文短信依赖 PDU 模式（模组文本模式有缺陷，已绕开）；
3. 「上网设置」页依赖社区固件自带的平台脚本，更换固件后该页可能失效，其余功能不受影响；
4. 只在 OpenWrt 22.03.7 实测；21.02 及更早不支持；
5. 转发未做去重与限流：同一条短信不会重复推送，但若模组异常重发，可能推两次。

## 常见问题

**Q：装完左侧菜单里没有「蜂助手面板」？**

A：确认固件版本 ≥ 22.03（21.02 的 LuCI 是 Lua 版，无法加载）；再刷新一次页面。

**Q：短信收得慢，或者干脆收不到？**

A：先看卡插在哪个槽。**EC200N 槽是秒级**；EC200T 槽走 CS 域轮询，15~30 秒，
且**部分联通卡 / 电信卡收不到**。**遇到收不到的情况，请把卡换到 EC200N 槽再试。**

**Q：转发没收到？**

A：① 确认页面上转发开关已勾选、渠道参数填写正确；② 可先用「通用 Webhook」做一次连通性测试；
③ 企业微信 / 钉钉 / 飞书需使用**群机器人的 webhook**，不是普通接口。

**Q：会影响原有的上网或其它功能吗？**

A：不会。面板不改动网络配置文件，装完即用、卸载即走；「上网设置」页只调整 mwan3 优先级，不重启设备。
